# Tally iOS — App Store release checklist

Everything in "Ready" is already in the repo and verified from a prebuild.
Everything in "Blocked" needs an Apple Developer account (or a decision) that
this repo cannot supply.

## Ready

| Item | Where | Verified by |
|---|---|---|
| `version` 1.0.0, `ios.buildNumber` 1 | `app.json` | `plutil -p ios/Tally/Info.plist` → `CFBundleShortVersionString 1.0.0`, `CFBundleVersion 1` |
| Export-compliance answer pre-filled | `app.json` → `ios.infoPlist.ITSAppUsesNonExemptEncryption: false` | same |
| Push background mode | `app.json` → `ios.infoPlist.UIBackgroundModes: ["remote-notification"]` | same |
| `aps-environment` entitlement | generated by the `expo-notifications` plugin | `ios/Tally/Tally.entitlements` contains `<key>aps-environment</key><string>development</string>` (EAS rewrites it to `production` for a store build) |
| Sign in with Apple entitlement | `app.json` → `ios.usesAppleSignIn` | entitlements contain `com.apple.developer.applesignin` = `Default` |
| Associated domains | `app.json` → `ios.associatedDomains` | entitlements contain `applinks:tally.app` |
| Camera usage description | `expo-image-picker` plugin `cameraPermission` | Info.plist `NSCameraUsageDescription` |
| Photo library usage description | `expo-image-picker` plugin `photosPermission` | Info.plist `NSPhotoLibraryUsageDescription` |
| No stray permission strings | `expo-image-picker` `microphonePermission: false`, `expo-secure-store` `faceIDPermission: false` | Info.plist has neither `NSMicrophoneUsageDescription` nor `NSFaceIDUsageDescription` (both were boilerplate for APIs the app never calls, and an unused string invites a review question) |
| Privacy manifest | generated by Expo prebuild | `ios/Tally/PrivacyInfo.xcprivacy` declares FileTimestamp / UserDefaults / SystemBootTime reasons, `NSPrivacyTracking false` |
| Build profiles | `eas.json` — `development`, `preview`, `preview-simulator`, `production` | `eas build --profile preview-simulator` |
| Version numbers | `cli.appVersionSource: "remote"` — EAS owns the build number from the first build on; `ios.buildNumber` is kept anyway because a local `expo prebuild` still reads it for `CFBundleVersion` (EAS logs a note that it ignores the field) | `eas build:view` reports `1.0.0 (1)` |
| Supabase config reaches cloud builds | `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` are EAS project variables (plain text) in the `development`, `preview` and `production` environments | `eas env:list`. `.env` is never uploaded, so a build made before these existed launched to a blank screen and quit |
| Upload size | `.easignore` excludes `node_modules`, `apps/web/.next`, `apps/mobile/ios`, screenshots | — |

Notifications need no `NSUserNotificationsUsageDescription`: iOS has no such key,
the permission is requested at runtime through `UNUserNotificationCenter`.
`NSPhotoLibraryAddUsageDescription` is not needed either — the app only reads
from the library (`expo-image-picker` launch modes), it never writes to it.

## Blocked on an Apple Developer account

1. **Signing** — `eas build --platform ios --profile preview` (and `production`)
   cannot generate a distribution certificate or provisioning profile without
   credentials. Run `eas credentials` once the account exists.
2. **TestFlight upload** — `eas submit --platform ios --profile production`
   needs `submit.production.ios` filled in with `appleId`,
   `ascAppId` and `appleTeamId` (the profile is an empty placeholder today).
3. **App Store Connect record** — bundle id `com.ballchen.tally` has to be
   registered before the first upload.

## Before the first submission

- [ ] **Replace the app icon.** `assets/icon.png` is the old green PWA mark; the
      app's identity is indigo `#5B5BD6`. The current file is a 1024×1024 opaque
      PNG (App Store requirement) upscaled from the 512px original, so it is
      valid but soft. Draw a fresh 1024×1024 indigo icon and keep
      `assets/splash-icon.png` (the transparent variant) for the splash screen.
- [ ] **Universal Links.** `applinks:tally.app` is declared but the domain
      serves no `/.well-known/apple-app-site-association`. Either publish an AASA
      file for the real web domain (with `appID: <TEAM_ID>.com.ballchen.tally`)
      or drop `associatedDomains` until the domain exists — a declared domain
      that fails validation is a review finding.
- [ ] **Enable the Apple provider in Supabase Auth** (Services ID, key id, team
      id, private key) so `expo-apple-authentication` → `signInWithIdToken` works
      outside the Simulator.
- [ ] **Push secrets.** Upload the APNs key to EAS (`eas credentials`) and set
      the `push-send` Edge Function's VAPID keys, so the web and Expo halves of
      the fan-out both work in production.
- [ ] **Privacy policy URL** and **support URL** for the App Store listing.
- [ ] **Account deletion disclosure.** App Review requires an in-app path
      (Settings → Delete account, already implemented) plus a note in the review
      notes saying where it lives.
- [ ] **App Store screenshots**: 6.9" (1320×2868 or 1290×2796) and 6.5"
      (1242×2688) portrait, at least 3 each. `docs/screens/*-light.png` are
      6.3" iPhone 17 Pro captures — usable as a starting point, not as the final
      upload sizes.
- [ ] **Decide on OTA updates.** No profile sets an update `channel`, because
      `expo-updates` is not installed. Add it (`npx expo install expo-updates`
      then `eas update:configure`) before relying on channels.
- [ ] **`eas submit`** once the credentials above exist; `production` already
      sets `autoIncrement`, and `cli.appVersionSource: "remote"` means EAS owns
      the build number from then on.
